# SAA Studio

一个支持中文、English 和中英对照的 AWS Certified Solutions Architect – Associate（SAA-C03）学习工作台：把课程、实验、刷题、复盘和打卡放在一起，按可持续的节奏准备考试。

**网站：<https://curtisatiwatt.github.io/saa/>**

默认计划为 **已有 AWS 使用经验，每周 10 小时，8 周完成约 80 小时学习**。这是一条建议路线；是否报考应由实际掌握情况决定。开始日期、每周投入时间和显示姓名可在「计划与数据设置」调整，网站会重新计算阶段日期并保留已完成进度。

## 可以做什么

- **24 课知识课程**：覆盖四大考试领域，每课有正文、场景决策、易错点、自测和 AWS 官方参考。
- **12 个实战实验**：包含 IAM、S3、VPC、Lambda、SQS、CloudWatch，以及数据库恢复、灾备和综合架构项目；每个步骤有验收标准和完成勾选，资源清理也计入完成条件。
- **120 道原创场景练习题**：单选和多选，提供答案、逐选项解析、知识点与官方文档来源；不是考试真题或题库转录。
- **专题练习与错题本**：按领域、主题、难度筛选；错题依据每道题最近一次作答更新，重练答对后自动移出，可写复盘笔记。
- **65 题、130 分钟模拟考试**：按四领域近似权重抽题，支持标记、题号跳转、续答和到时交卷；交卷后统一查看解析。
- **学习计划与进度面板**：任务、课程和实验完成状态，最近正确率、领域表现、连续学习天数及建议目标窗口。
- **三种语言模式**：`zh` 中文、`en` English、`bi` 中英对照，覆盖界面、课程、实验、题目和解析；切换语言保留学习与答题进度。
- **可选加密云同步**：使用私人配对码连接设备，支持离线修改合并与正在进行的练习续答；需先部署并配置同步服务，见下文。
- **本地笔记与可选 JSON 备份**：不启用云同步也可以学习；随时导出进度，或预览并确认导入备份。

题库有限，多次模拟可能遇到重复题。本站模拟按全部 65 题计算正确率，不复刻 AWS 的未计分题安排或量表换算。

## 八周学习路线

建议把每周 10 小时拆成工作日短时段与周末实践；前六周围绕概念、实验、练习和复盘分配时间，最后两周把更多时间留给完整模拟与补弱。每周任务合计精确 600 分钟。

| 周 | 重点 | 本周交付 |
| --- | --- | --- |
| 1 | 架构基础、IAM、VPC 与混合连接 | 费用护栏、资源台账、最小权限策略与测试记录 |
| 2 | EC2、负载均衡、伸缩、S3 与文件系统 | S3 版本恢复、双 AZ 网络图与故障推演 |
| 3 | RDS、Aurora、DynamoDB 与缓存 | 无状态伸缩设计、数据库选型与恢复 runbook |
| 4 | Lambda、容器、SQS/SNS 与工作流 | Lambda 成功/失败观察、消息重试和 DLQ 验证 |
| 5 | 全球交付、安全、监控与灾难恢复 | 故障调查记录、RTO/RPO 恢复方案及成本比较 |
| 6 | 分析、迁移、计算与存储成本 | 可展示的可靠订单平台架构项目 |
| 7 | 综合做题法、第一次完整模拟 | 错因清单、两个薄弱主题补课、架构答辩与清理审计 |
| 8 | 第二次模拟、官方未见题与最终补弱 | 有依据的报考或延期决定 |

实验既有少量实际云资源操作，也有无需部署资源的架构练习。**免费额度不作保证**；执行前阅读成本说明，使用专用练习环境，不把真实密钥、客户数据或生产配置写入笔记，完成后按清单清理。AWS Budgets 通知可能延迟，不是实时消费硬上限。

## 如何判断准备好了

网站提供以下学习目标，作为自评参考：

1. 完成学习任务与全部实验验收、资源清理，能解释主要架构取舍。
2. 最近两次完整限时模拟均达到 80% 以上。
3. 四个领域各练至少 10 题，最近作答正确率均达到 75% 以上。
4. 另外做未见过的 AWS 官方练习，检查自己掌握的是推理，而不是答案记忆。

这些标准**不保证通过考试**。如果还不能解释错误选项，或某个领域持续薄弱，建议增加 1–2 周针对性复习。

考试核心事实核对于 **2026-11-13**：SAA-C03 为 65 题、130 分钟，含 50 道计分题及 15 道未标明的不计分题；四领域权重为安全 30%、弹性 26%、高性能 24%、成本优化 20%。官方最低通过量表分为 **720（量表范围 100–1000），不等于答对 72%**。预约前应再次查看最新官方要求。

## 语言与学习进度

页面语言选择器提供中文（`zh`）、English（`en`）和中英对照（`bi`）。中英文内容使用相同的课程、题目和任务 ID；语言切换不会重新抽题或清除答案。显示语言是当前浏览器的偏好，不强制同步到其他设备。

## 本地保存与可选云同步

网站首先把进度保存在当前浏览器的 `localStorage`，学习数据键为 `saa-studio-v1`。任务、课程、实验、笔记、答题记录和未完成练习在本地即可使用。**只有主动连接云同步后，才会把加密的进度文档发送给配置的同步服务。**

云同步代码使用浏览器 Web Crypto：随机生成的私人配对码通过 HKDF 分别派生认证令牌和 AES-256-GCM 加密密钥。每次上传使用新的随机 IV。服务端只接收认证令牌和密文，数据库只保存令牌的 SHA-256 标识、密文、版本与限流元数据；配对码和加密密钥不发送到服务端。

连接另一台设备的流程是：

1. 在第一台设备的设置中创建云同步空间，并妥善保存私人配对码。
2. 在另一台设备输入同一配对码，连接同一个空间；已有本地进度会参与合并。
3. 确认显示同步成功，再离开当前设备。离线时仍可继续学习，恢复连接后重试同步。

**配对码相当于这个空间的完整读写权限。** 不要放在公开仓库、网址、截图或聊天中。代码会将配对信息保存在浏览器的 `saa-studio-sync-v1` 中；本地学习数据仍是明文，本功能不提供设备磁盘或浏览器扩展层面的加密保护。

如果一台浏览器丢失了本地数据，可用保存的配对码或另一台已配对设备恢复连接；如果**所有配对设备和配对码都丢失，服务端无法找回密钥或解密进度**。没有邮箱账号、密码重置或管理员恢复功能。断开某台设备的同步会保留该设备的本地学习记录，并移除该设备保存的配对信息；它不删除服务器上的密文，也不会撤销其他设备已持有的配对码。

### 合并规则与练习续答

- 不同任务、课程、实验步骤和笔记的修改可以合并；同一个字段发生冲突时，按混合逻辑时钟采用较新的写入（last-write-wins）。删除或取消完成也会参与同步。
- 已观察到云端修改之后的本地编辑会排在它之后。真正同时离线的冲突无法推断绝对真实先后；时间相同时用设备 ID 确定一致的结果。同一篇笔记的并发编辑不会逐段合并，可能保留其中一份。
- 答题与已完成练习记录按标识去重合并；学习活动按日期保留观察到的较大计数，不简单把设备计数相加。
- 同一场练习在不同设备上作答时，按题目合并答案、提交状态和标记；同一题的冲突仍采用上述规则。两台设备同时新建**不同**练习时，仅保留逻辑时间较新的那场作为当前练习，不会把两套题拼接起来。
- 同一场模拟考试保留原始开始时间与截止时间。换设备、刷新或离线不会重启或延长 130 分钟计时；重新打开时已过期的考试会结算。已交卷的练习不会被旧设备重新变成进行中。
- 连接云同步时执行「清空学习数据」会同步这一重置；旧的离线副本不会自动把已清空内容恢复回来。仅想停止同步时，应使用断开连接。

### 容量与手动备份

单个云端密文文档上限为 **1 MiB（1,048,576 字节，包含 16 字节认证标签）**。文档还包含合并时钟，因此可同步的学习正文会小于该上限。超过上限时，网站保留本地进度并提示同步失败，不会悄悄截断云文档。本地目前保留最多 20,000 次作答、500 次已完成练习，每条笔记最多 20,000 字符；浏览器自身的存储配额仍可能先成为限制，这些记录上限也不保证全部装进 1 MiB 云空间。

JSON 导出/导入是**可选的额外备份**，不要求每次切换设备都操作。导出的是学习进度快照，不包含私人配对码；它不能替代配对码的保管。备份含笔记与答题信息且不是加密文件，请妥善保存。导入会替换当前本地进度；如果已连接云同步，导入结果也会按应用的替换/合并流程同步。

清除站点数据、隐私浏览会话结束、浏览器回收存储或更换浏览器，都可能删除本地进度及配对信息。本地预览与 GitHub Pages 属于不同来源，需要分别配对或用备份迁移。页面完全关闭时没有后台同步服务，离开前检查同步状态。

网站不会连接 AWS 账户验证实验资源。勾选实验完成是自我确认。GitHub Pages 和 Cloudflare 等托管方仍可能处理常规访问元数据；创建限流只在应用数据库中保存按小时哈希的 IP 标识，不保存原始 IP。这些标识属于化名化数据，并不代表网络访问匿名。

## 同步后端的部署状态

源码包含独立 Cloudflare Worker 与 D1 后端。**本次文档更新时，生产后端尚未完成部署验证**；未配置端点时云同步不可用，本地学习仍可正常使用。

预期公开地址仅作为配置目标：`https://saa-progress-sync.curtis-atiwatt.workers.dev`。维护者应先完成部署、真实 API 检查和浏览器配对验证，再将实际地址填入 `sync-config.js` 的 `SYNC_ENDPOINT`。不要把配对码、认证令牌或加密密钥写入此文件。

具体数据库初始化、`DB` 绑定、兼容日期、API 协议和验证步骤见 [cloud/README.md](cloud/README.md)。GitHub Pages 流程只发布静态前端，不自动发布 Worker 或执行 D1 schema。

## 本地开发与检查

使用 **Node.js 22.13.0 或更新版本**。前端运行时为原生 HTML、CSS 和 JavaScript ES modules，没有第三方运行时或构建依赖，无需 `npm install`。后端测试使用 Node 内置 `node:sqlite`，所以完整测试需要上述 Node 版本。

```bash
npm test
npm run build
npm run dev
```

开发预览地址为 <http://127.0.0.1:4187/saa/>。请通过 HTTP 服务器访问，不要直接双击 `index.html`，因为浏览器对 `file://` 下的模块加载有限制。

构建结果位于 `dist/`，可单独预览部署产物：

```bash
node scripts/serve.mjs --dist
```

两种预览使用同一端口，启动前先停止另一个服务。`npm test` 使用 Node 内置测试运行器，包含评分/内容、加密、离线合并、同步客户端和 Worker API 测试。Worker 测试用 D1 形状的适配器在真实内存 SQLite 上执行 schema、SQL 和事务，不访问生产服务；这不替代部署后的真实 Workers/D1 验证。`npm run build` 把网站文件与双语题库、课程数据复制到 `dist/`，无需打包器。

## GitHub Pages 发布

源码仓库为 [curtisatiwatt/saa](https://github.com/curtisatiwatt/saa)，发布目标为 <https://curtisatiwatt.github.io/saa/>。仓库中的 GitHub Actions 发布流程负责检查、构建、上传 Pages artifact 并部署 `dist/`。

仓库设置应为：

1. **Settings → Pages → Build and deployment → Source：GitHub Actions**。
2. 推送到发布分支 `main` 后，在 **Actions** 查看发布流程及测试、构建、部署结果；也可在流程页面手动触发。
3. 工作流需具备读取源码、写入 Pages 部署和获取 OIDC token 所需权限，部署使用 `github-pages` 环境。
4. 等待部署成功后访问正式网址。若失败，先查看对应 job 日志，检查 Pages 是否启用、环境保护规则与仓库权限。

页面采用相对资源路径和 hash 路由，适用于 `/saa/` 项目子路径，刷新课程或实验链接不需要服务端路由规则。构建中保留 `.nojekyll`。
